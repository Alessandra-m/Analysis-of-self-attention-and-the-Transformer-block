# Разобрать self-attention и реализовать блок Transformer

**Предложение авторов**

Отказ от рекуррентности и свёрток полностью в пользу построения обработки последовательности целиком на механизме внимания. 

Почему это важно именно для encoder'а: раньше, чтобы слово «узнало» о других словах фразы, сигнал должен был пройти через цепочку рекуррентных шагов (в RNN — буквально слово за словом). Чем дальше два слова друг от друга, тем длиннее путь и тем хуже выучивается связь. Авторы заменяют это на self-attention, где любое слово соединяется с любым другим напрямую, за одну операцию, и всё считается параллельно по всем позициям сразу. В терминах их таблицы сложности: путь между двумя позициями становится $O(1)$ вместо $O(n)$ у рекуррентного слоя.

**Назначение Q, K, V**

Внимание — это механизм, где каждое слово собирает информацию с других слов. Чтобы это формализовать, каждому слову дают три разные роли, и это три разных обучаемых проекции одного и того же входного вектора:

- Query (запрос) — «что я ищу». Это вектор слова-в-роли-ищущего. Именно query решает, на что данное слово будет смотреть.
- Key (ключ) — «чем я могу быть полезен / как меня найти». У каждого слова есть key, с которым сравнивается чужой query.
- Value (значение) — «что я отдам, если на меня обратят внимание». Это содержимое, которое реально подмешается в результат.

Механика связывает их так: берём query одного слова, считаем его скалярное произведение с key каждого слова — получаем «оценки похожести». Прогоняем оценки через softmax → получаем веса, сумма которых равна 1. Берём взвешенную сумму value всех слов с этими весами. Результат — новое представление слова, обогащённое контекстом.

Q, K, V получаются из одного и того же входа (в self-attention), но через три разные матрицы проекций $W^Q, W^K, W^V$. Именно это разделение ролей даёт гибкость — сравнение (Q·K) и передаваемое содержимое (V) живут в разных пространствах и обучаются независимо. Если бы роль была одна, слово могло бы только «притягивать похожих на себя», а так оно может искать по одному признаку, а отдавать совсем другой.

Маленькая аналогия, чтобы осело: это как поиск в базе. Query — текст твоего запроса, keys — заголовки записей (по ним ищем совпадение), values — сами записи (их и возвращаем). Разница только в том, что здесь «совпадение» мягкое: не одна запись, а взвешенная смесь всех, пропорционально релевантности.
