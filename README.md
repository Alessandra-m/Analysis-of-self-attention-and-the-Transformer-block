## 1. Предложение авторов и назначение Q, K, V

**Предложение авторов**

Отказ от рекуррентности и свёрток полностью в пользу построения обработки последовательности целиком на механизме внимания.

Почему это важно именно для encoder'а: раньше, чтобы слово «узнало» о других словах фразы, сигнал должен был пройти через цепочку рекуррентных шагов (в RNN — буквально слово за словом). Чем дальше два слова друг от друга, тем длиннее путь и тем хуже выучивается связь. Авторы заменяют это на self-attention, где любое слово соединяется с любым другим напрямую, за одну операцию, и всё считается параллельно по всем позициям сразу. В терминах их таблицы сложности: путь между двумя позициями становится $O(1)$ вместо $O(n)$ у рекуррентного слоя.

**Назначение Q, K, V**

Внимание — это механизм, где каждое слово собирает информацию с других слов. Чтобы это формализовать, каждому слову дают три разные роли, и это три разных обучаемых проекции одного и того же входного вектора:

- **Query (запрос)** — «что я ищу». Это вектор слова-в-роли-ищущего. Именно query решает, на что данное слово будет смотреть.
- **Key (ключ)** — «чем я могу быть полезен / как меня найти». У каждого слова есть key, с которым сравнивается чужой query.
- **Value (значение)** — «что я отдам, если на меня обратят внимание». Это содержимое, которое реально подмешается в результат.

Механика связывает их так: берём query одного слова, считаем его скалярное произведение с key каждого слова — получаем «оценки похожести». Прогоняем оценки через softmax → получаем веса, сумма которых равна 1. Берём взвешенную сумму value всех слов с этими весами. Результат — новое представление слова, обогащённое контекстом.

Q, K, V получаются из одного и того же входа (в self-attention), но через три разные матрицы проекций $W^Q, W^K, W^V$. Именно это разделение ролей даёт гибкость — сравнение (Q·K) и передаваемое содержимое (V) живут в разных пространствах и обучаются независимо. Если бы роль была одна, слово могло бы только «притягивать похожих на себя», а так оно может искать по одному признаку, а отдавать совсем другой.

## 2. Scaled dot-product attention

Вся операция внимания умещается в одну формулу:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

Реализация (`scaled_dot_product_attention` в `transformer.py`):

```python
def scaled_dot_product_attention(Q, K, V, mask=None):
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / d_k ** 0.5
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))
    weights = F.softmax(scores, dim=-1)
    output = weights @ V
    return output, weights
```

- `Q @ K.transpose(-2, -1)` — матрица похожестей формы `(..., T_q, T_k)`: элемент `[i, j]` — насколько запрос `i` хочет посмотреть на ключ `j`. Транспонируем именно последние две оси, чтобы ведущие оси батча и голов остались на месте.
- `/ d_k ** 0.5` — масштабирование на $\sqrt{d_k}$. Без него при больших $d_k$ скалярные произведения разрастаются, softmax уходит в насыщение (один вес ≈ 1, остальные ≈ 0), и градиенты становятся почти нулевыми. Деление возвращает их в рабочий масштаб.
- `masked_fill(mask == 0, -inf)` — опциональная маска: там, где смотреть запрещено, ставим $-\infty$, и после softmax этим позициям достаётся нулевой вес (causal-маска декодера, маскирование паддинга). В чистом encoder-self-attention не нужна.
- `softmax(..., dim=-1)` — нормировка по **последней** оси (по ключам), чтобы для каждого запроса веса по всем ключам давали в сумме 1.
- `weights @ V` — взвешенная сумма значений, форма `(..., T_q, d_v)`. Ось ключей схлопывается.

**Сверка со встроенной реализацией.** Результат сверяется с `F.scaled_dot_product_attention` на случайных данных:

```
scaled dot-product attention:  True
tensor(2.3842e-07)
```

`True` означает совпадение с эталоном; `2.38e-07` — не ошибка, а естественный шум float32 (предел точности одинарной точности при таком числе сложений). Две оговорки: встроенная версия возвращает только `output` (без весов), а её аргумент `attn_mask` использует обратное соглашение (`True` = «оставить», тогда как здесь `mask == 0` = «запретить»).

## 3. Encoder-блок: multi-head attention, MLP, residual + LayerNorm

**Multi-head attention.** Вместо одного внимания на всю размерность `d_model` режем её на `num_heads` голов, в каждой считаем внимание независимо той же функцией, потом склеиваем. Размерность головы `d_k = d_model / num_heads` (в статье `512 / 8 = 64`). «Нарезка на головы» — это просто reshape, без цикла: головы живут как ещё одна ось тензора и считаются параллельно.

```python
Q = Q.view(B, T, self.num_heads, self.d_k).transpose(1, 2)  
out = out.transpose(1, 2).contiguous().view(B, T, self.d_model)   
out = self.W_o(out)                                               
```

`W_q, W_k, W_v` — проекции входа в Q, K, V; `W_o` — проекция склеенного результата (в формуле статьи $W^O$), без неё головы остались бы независимыми блоками. `contiguous()` обязателен: после `transpose` память лежит вперемешку, а `view` требует непрерывной раскладки.

**Feed-forward (MLP).** Два линейных слоя с ReLU между ними, применяются к каждой позиции независимо:

$$\text{FFN}(x) = \max(0,\ xW_1 + b_1)\,W_2 + b_2$$

Первый слой расширяет `d_model → d_ff` (в статье 512 → 2048, в 4 раза шире), второй сжимает обратно `d_ff → d_model`. Параметры одинаковы для всех позиций, но свои у каждого слоя стека.

**Residual + LayerNorm.** Каждый из двух подслоёв обёрнут по формуле статьи $\text{LayerNorm}(x + \text{Sublayer}(x))$:

```python
attn_out, weights = self.attn(x, mask)
x = self.norm1(x + self.dropout(attn_out))   # подслой 1: внимание
ff_out = self.ff(x)
x = self.norm2(x + self.dropout(ff_out))      # подслой 2: FFN
```

- `x + Sublayer(x)` — остаточная связь. Прибавление исходного `x` позволяет складывать 6 слоёв без затухания градиента (тот же приём, что в ResNet). Именно поэтому все подслои держат одинаковую размерность `d_model` — иначе `x` и `Sublayer(x)` нельзя было бы сложить.
- `LayerNorm` нормирует каждый токен по его признакам (по оси `d_model`), стабилизируя распределение активаций.
- `Dropout` применяется к выходу подслоя перед прибавлением (в `eval()` выключается).
- У каждого подслоя свой `LayerNorm` — у нормировки обучаемые параметры масштаба и сдвига, их нельзя переиспользовать.

## 4. Размеры тензоров и влияние числа токенов

Проход одного encoder-блока с параметрами `B=2`, `H=4`, `T=5`, `d_model=32`, `d_k = 32/4 = 8`:

| Шаг | Форма |
|---|---|
| вход `x` | `(2, 5, 32)` — `(B, T, d_model)` |
| после `W_q/W_k/W_v` | `(2, 5, 32)` каждый |
| нарезка на головы | `(2, 4, 5, 8)` — `(B, H, T, d_k)` |
| **`scores = Q·Kᵀ`** | **`(2, 4, 5, 5)` — `(B, H, T, T)`** |
| после softmax | `(2, 4, 5, 5)` |
| `weights·V` | `(2, 4, 5, 8)` |
| склейка голов + `W_o` | `(2, 5, 32)` |
| + residual, LayerNorm, FFN | `(2, 5, 32)` |

Почти везде размер линеен по `T`. Единственное исключение — `scores` формы `(B, H, T, T)`, то есть `T×T` на каждую голову. Это единственное место, где `T` входит в квадрате.

**Влияние числа токенов.** Из таблицы сложности в статье: у self-attention сложность слоя $O(T^2 \cdot d)$ при $O(1)$ последовательных операций (всё параллельно); у рекуррентного слоя — $O(T \cdot d^2)$ при $O(T)$ последовательных шагов. Отсюда:

- **По скорости** self-attention выигрывает у RNN, пока `T < d` (обычные предложения: слов меньше, чем размерность). Но член `T²` делает внимание узким местом на длинных последовательностях.
- **По памяти** тензор весов `(B, H, T, T)` надо хранить для обратного прохода. Для модели размера из статьи (`H=8`, `B=1`, float32, на один слой):

| `T` | матрица внимания (на слой) |
|---|---|
| 512 | ~8 МБ |
| 1024 | ~34 МБ |
| 2048 | ~134 МБ |
| 4096 | ~537 МБ |

Увеличивается в ~4 раза с каждым удвоением `T`, и это ещё умножается на число слоёв. Отсюда и стоимость «длинного контекста», и мотивация разреженного/линейного внимания (в статье упомянуто restricted self-attention с окном `r`, снижающим путь до $O(T/r)$).
